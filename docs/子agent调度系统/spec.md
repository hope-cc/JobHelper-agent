# 子Agent调度系统 Spec

## 背景

当前 JobHelper 的 ReAct 循环是单 agent 模式：主 agent 一次只能串行调用工具。在处理招聘网站批量抓取场景时存在瓶颈——主 agent 分析页面后发现 N 条公司列表，需要逐一调用 click 工具进入详情页、再用 getTextFromURL 抓取简章。若串行执行，N 条记录耗时 = N × 单次耗时，且主 agent 在此期间被阻塞，无法与用户交互。

需要引入**子 agent 调度系统**：主 agent 分析出任务列表后，将列表交给调度器，调度器按并发数管理多个子 agent 并行执行，主 agent 立即恢复控制权；子 agent 完成后结果异步注入对话上下文。

## 目标

- 主 agent 能将批量任务（JSON 列表）通过工具调用交给调度器，**不等待**子 agent 完成即恢复控制
- 调度器严格按照可配置的并发数创建和管理子 agent 池
- 每个子 agent 是独立 LLM 实例，一次只处理一个任务，完成后获得下一个
- 子 agent 完成后结果异步注入主 agent 对话上下文
- 调度逻辑（任务派发、并发控制、完成信号）与业务逻辑（任务内容、提示词、子 agent 上下文）解耦

## 功能需求

- **F1：任务列表接收** — 调度器接收一个 JSON 数组作为输入，数组中每个元素代表一项待执行的任务。任务的具体字段（如 url、操作类型等）由业务层定义，调度器不关心，原样透传给子 agent。

- **F2：并发控制** — 调度器维护一个可配置的并发上限（如 max_concurrency=3）。同时运行的子 agent 数量不超过此值。未达到上限时立即分配任务；达到上限时任务排队等待。

- **F3：任务派发与完成信号** — 调度器从任务列表中按顺序逐一取出任务，分配给空闲的子 agent。子 agent 完成当前任务后通过信号（回调/事件）通知调度器，调度器将结果收集并分配下一项任务。每个子 agent 的生命周期内处理 0 项或多项任务。

- **F4：调度器作为工具** — 调度器暴露为一个可供主 agent 调用的工具。主 agent 调用时传入任务列表 JSON 和并发数，工具内部创建后台 asyncio Task 启动调度循环后立即返回（不阻塞主 agent）。返回值是一个调度摘要（如"已启动 3 个子 agent 处理 5 项任务"）。

- **F5：结果回调接口** — 调度器提供结果回调接口（如 `on_task_complete` 回调函数），子 agent 完成任务时调用此接口传出结果。具体的结果注入逻辑（如何写入对话上下文）由调用方实现，调度器不关心。

- **F6：调度生命周期结束** — 所有任务执行完毕后（无论成功或失败），调度器清理子 agent 资源，发送完成通知。

- **F7：错误隔离** — 单个子 agent 或单条任务执行失败不影响其他任务和调度器整体运行。失败信息记录在对应的任务结果中。

## 非功能需求

- **N1：并发安全** — 调度器在多子 agent 并发场景下使用 asyncio 同步原语（如 `asyncio.Semaphore`），确保任务队列的读写无竞态。

- **N2：可配置并发数** — 并发上限在调度器初始化时通过参数传入，运行期可读取但不可动态修改（简化初始版本）。

- **N3：调度与业务解耦** — 调度器核心类不依赖 LLM 客户端类型、工具注册中心、具体任务字段。它只管理"任务项的派发和结果收集"这一抽象流程。

- **N4：可测试** — 调度核心逻辑可在不启动真实 LLM 的情况下通过 mock 子 agent 函数进行单元测试。

## 不做的事

- **不做**：子 agent 的上下文管理、提示词构造（由调用方实现）
- **不做**：任务列表的具体 JSON 字段定义（由业务层定义）
- **不做**：F5 结果回调的具体注入逻辑（留接口，由调用方实现）
- **不做**：子 agent 之间的通信或协作
- **不做**：调度器的暂停/恢复/动态扩缩容
- **不做**：任务持久化或断点续传

## 验收标准

- **AC1**：调度器接收一个包含 5 项任务的 JSON 列表，设置并发数=2，可观测到最多同时只有 2 个子 agent 在执行，5 项任务全部完成。
- **AC2**：用 mock 子 agent 函数（模拟不同耗时）验证任务按完成顺序触发回调，而非按提交顺序。
- **AC3**：某项任务 mock 抛出异常时，调度器继续分配后续任务，异常信息记录在结果回调中。
- **AC4**：调度器作为 `dispatch_tasks` 工具注册到 ToolRegistry，主 agent 可正常调用并立即获得返回（不阻塞）。
- **AC5**：任务列表为空或并发数为 0 时，调度器优雅处理（不抛异常，立即返回）。
