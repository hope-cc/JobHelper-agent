# JobHelper 前端 Spec

## 背景
当前 JobHelper 只支持终端交互。用户通过命令行选择 LLM 供应商、输入问题、查看流式回复。
这种方式存在以下问题：
- 体验受限：无法展示富文本、代码高亮、思考过程折叠等
- 无会话管理：每次启动是全新的对话，无法回顾历史
- 功能入口不直观：简历管理、投递进度等规划功能没有入口

项目已有的后端能力：
- 多供应商 LLM 调用（Anthropic / OpenAI 协议）
- 流式事件输出（TextChunk、ThinkingChunk、ToolCall* 等）
- LangGraph 图定义（单节点对话图，预留扩展）
- YAML 配置管理

## 目标
用 React SPA 替代终端交互，提供类似 ChatGPT 的 Web 体验：
1. 侧边栏布局（1/7 宽），包含功能导航和会话历史
2. 主区域支持新对话和查看历史对话
3. 新增 FastAPI 后端，将现有 LLM 调用能力封装为 HTTP + SSE 接口
4. 聊天记录以 JSON 文件持久化

## 功能需求

### F1: 侧边栏布局
页面左侧 1/7 区域为固定边栏。上方为功能导航区，下方为会话历史区。
会话历史区可垂直滚动，超出部分显示滚动条。

### F2: 功能导航
上方区域包含三个导航入口：新聊天、简历管理、投递进度。
点击后右侧主区域对应切换内容。当前选中的导航项有高亮状态。

### F3: 新建对话
右侧主区域初始显示一个居中对话框。用户输入问题并发送后：
- 界面切换为可滚动的聊天记录视图
- 流式展示 LLM 回复（文本逐字出现）
- 对话完成后，侧边栏自动新增一条会话记录
- 新会话的标题由首条用户消息的前若干个字符自动生成

### F4: 会话历史
侧边栏下方区域列出所有历史会话，每条显示标题。
点击某条历史会话，右侧主区域加载该会话的完整聊天记录并滚动展示。
当前查看的会话在列表中高亮。

### F5: 简历管理页面（占位）
点击"简历管理"导航时，右侧显示空白占位页面，提示"该功能将在后续版本开发"。

### F6: 投递进度页面（占位）
点击"投递进度"导航时，右侧显示空白占位页面，提示"该功能将在后续版本开发"。

### F7: 后端 API
FastAPI 提供以下接口：
- 获取会话列表
- 获取指定会话的聊天记录
- 发送消息并返回 SSE 流式响应
- 创建新会话

### F8: 会话持久化
会话数据以 JSON 文件存储在服务端。每个会话一个 JSON 文件，包含会话元信息
（标题、创建时间）和消息列表（每条消息包含角色和内容）。

## 非功能需求

- N1: 前端使用 Vite + React + Tailwind CSS 构建
- N2: 后端使用 FastAPI，SSE 用于流式传输 LLM 回复
- N3: 前端与后端通过 HTTP REST API + SSE 通信
- N4: 聊天记录的 JSON 文件存储在服务端文件系统中

## 不做的事

- 用户认证 / 登录
- 简历管理的实际功能
- 投递进度的实际功能
- 数据库（本阶段仅用 JSON 文件）
- 多设备同步
- 会话删除 / 重命名
- Tool Calling 的 UI 展示
- 移动端适配

## 验收标准

- AC1: 打开页面后，左侧边栏可见，包含功能导航和空的会话历史区
- AC2: 点击"新聊天"，右侧显示居中对话框，可输入并发送消息
- AC3: 发送消息后，LLM 回复以流式方式逐字出现
- AC4: 对话完成后，侧边栏自动出现一条新会话记录，标题为首条消息的前若干字符
- AC5: 点击侧边栏中的历史会话，右侧加载并显示该会话的完整聊天记录
- AC6: 点击"简历管理"和"投递进度"，分别显示对应的占位页面
- AC7: 刷新页面后，历史会话列表依然存在（从 JSON 文件读取）
- AC8: 支持多轮对话，上下文不会丢失
