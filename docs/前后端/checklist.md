# JobHelper 前端 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [ ] [后端存储] storage.py 存在且 5 个函数可被导入（验证：`python -c "from src.api.storage import list_conversations, get_conversation, create_conversation, add_message, update_title"` 无报错）
- [ ] [后端 SSE] sse.py 正确转换事件类型（验证：构造 TextChunk，调用 to_sse，输出含 `event: text`）
- [ ] [后端路由] 4 个 API 端点正常响应（验证：curl 测试每个端点，均返回非 500 状态码）
- [ ] [后端入口] FastAPI 服务可启动（验证：`python -m src.api.main` 无报错，浏览器访问返回数据）
- [ ] [前端项目] Vite 开发服务器可启动（验证：`npm run dev` 无编译报错）
- [ ] [前端类型] TypeScript 类型定义完整（验证：`npx tsc --noEmit` 通过）
- [ ] [前端 API 客户端] 4 个函数封装正确（验证：console 调用各函数，网络请求正常发出）
- [ ] [状态管理] AppContext reducer 覆盖所有 action 类型（验证：组件中调用各 dispatch，状态正确更新）
- [ ] [占位页] 简历管理和投递进度均显示占位文案（验证：点击导航，右侧显示预期文本）
- [ ] [侧边栏] 导航切换 + 会话列表渲染（验证：点击三个导航，视图切换；会话列表正确渲染）
- [ ] [消息气泡] user 和 assistant 消息区分布局（验证：发送消息后，两类消息对齐方向不同）
- [ ] [欢迎页] 居中输入框可发送消息（验证：输入文本发送，界面切换到聊天视图）
- [ ] [聊天视图] 消息列表可滚动，底部输入框固定（验证：发送多条消息后刷新列表，滚动正常）
- [ ] [主区域] 根据 view 正确切换子组件（验证：点击不同导航，右侧内容对应切换）
- [ ] [根组件] AppProvider + 布局正确（验证：打开页面，左侧边栏 + 右侧主区域按 1:6 比例显示）

## 集成

- [ ] 前端 API 代理正确转发到后端（验证：前端 `npm run dev`，后端 `python -m src.api.main`，发送消息能收到 LLM 回复）
- [ ] SSE 流式响应在前端正确解析（验证：发送消息后，LLM 回复逐字出现，非一次性显示）
- [ ] 会话数据持久化到 JSON 文件（验证：发送消息后检查 `data/conversations/` 目录，对应 JSON 文件存在且内容正确）
- [ ] 前端未独立于后端的状态管理（验证：前端通过 API 获取状态，不自己维护与后端重复的完整数据源）

## 编译与测试

- [ ] 前端 TypeScript 编译无错误（验证：`npx tsc --noEmit`）
- [ ] 前端 Vite 构建成功（验证：`npm run build` 无报错，生成 dist 目录）
- [ ] Python 后端无 import 错误（验证：`python -c "from src.api.main import app"` 无报错）

## 端到端场景

- [ ] 场景 1 — 首次使用：打开页面 → 左侧边栏显示三个导航，会话列表为空 → 点击"新聊天" → 右侧显示居中输入框 → 输入"帮我看看Python开发岗的就业前景" → 发送 → 界面切换到聊天视图，LLM 回复流式出现 → 回复完成后，侧边栏出现一条标题为"帮我看看Python开发岗的就业前景"的会话记录
- [ ] 场景 2 — 继续已有会话：在聊天视图中输入第二个问题"那和Java相比呢？" → 发送 → LLM 基于上下文理解"和Java相比"的含义 → 流式回复正常出现
- [ ] 场景 3 — 查看历史：点击侧边栏中的历史会话 → 右侧加载该会话的完整聊天记录 → 可以滚动查看所有消息
- [ ] 场景 4 — 新建第二个会话：点击"新聊天" → 输入全新问题 → 侧边栏出现第二条会话记录 → 两条记录按创建时间排列
- [ ] 场景 5 — 占位页面：点击"简历管理" → 右侧显示占位文案 → 点击"投递进度" → 右侧显示占位文案 → 点击"新聊天" → 回到对话框
- [ ] 场景 6 — 刷新持久化：刷新浏览器页面 → 侧边栏仍显示之前创建的会话列表 → 点击某个会话 → 聊天记录完整加载
