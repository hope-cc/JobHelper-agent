# 投递进度管理 Spec

## 背景

JobHelper 侧边栏已有「投递进度」入口，目前渲染为占位页（`PlaceholderPage`）。规划中，投递进度用于记录用户在秋招/春招期间的投递、测评与反馈，帮助随时掌握求职节奏。

本期把「投递进度」做成完整可用的数据管理模块：提供记录的新增、编辑、查看、搜索、筛选、排序与 CSV 导出，并带实时统计卡片。数据走后端 API + JSON 文件持久化（沿用个人信息管理模块的 storage/routes 模式），初始为空数据。

## 目标

- 将「投递进度」占位页替换为功能完整的投递记录管理页
- 提供 5 张统计卡片：全部记录、进行中、已获 Offer、已拒绝、本月投递
- 每条投递记录包含：投递时间、公司、岗位、进度状态、下一步行动、备注
- 提供「新增记录」「编辑」交互，落库到 `data/jobs.json`
- 提供搜索、进度筛选、时间排序、导出 CSV
- 视觉上遵循现代极简 + 轻量拟态风格（浅冷灰背景、白色圆角卡片、深蓝主色、状态胶囊徽标）

## 功能需求

### F1 页面与导航

- F1.1：点击侧边栏「投递进度」进入本页，替换现有占位页 `PlaceholderPage`
- F1.2：页面按「顶部 Header → 统计卡片栏 → 表格主卡片」三段纵向排布

### F2 顶部 Header 区域

- F2.1：左侧小副标「秋招投递记录」（浅蓝色加粗小字）
- F2.2：左侧主标题「秋招投递进度」（大字号深色加粗）
- F2.3：左侧描述文案「记录投递、测评和反馈，随时掌握求职节奏」（浅灰副文）
- F2.4：右侧「+ 新增记录」主操作按钮（深蓝底白字、圆角、悬停反馈）

### F3 统计卡片栏（Metric Cards）

- F3.1：横向 5 张统计卡片，自适应网格 `grid-cols-5`，白底圆角 + 浅灰边框
- F3.2：卡片 1「全部记录」= 记录总数，主色深蓝大数字
- F3.3：卡片 2「进行中」= 状态为「简历已投递」或「评估中」的记录数
- F3.4：卡片 3「已获 Offer」= 状态为「Offer」的记录数
- F3.5：卡片 4「已拒绝」= 状态为「已拒绝」的记录数
- F3.6：卡片 5「本月投递」= 投递时间在当前自然月的记录数
- F3.7：无数据时各卡片显示 0

### F4 投递记录字段

- F4.1：单条记录字段：`id`、`company`（公司）、`position`（岗位）、`applied_at`（投递时间，日期）、`status`（进度，四选一）、`next_step`（下一步行动）、`remark`（备注，可选）
- F4.2：表格列与设计稿一致：`时间 | 公司 | 岗位 | 进度 | 下一步 | 操作`；备注不单独成列
- F4.3：公司名称加粗展示

### F5 新增记录

- F5.1：点击「+ 新增记录」弹出表单对话框
- F5.2：表单字段：投递时间（日期选择/文本）、公司名称、岗位名称、进度（下拉四选一）、下一步行动、备注（可选）
- F5.3：提交后新记录写入后端并持久化，表格与统计卡片即时刷新

### F6 编辑记录

- F6.1：表格「操作」列提供「编辑」文字按钮（蓝色）
- F6.2：点击后弹出预填的编辑表单
- F6.3：保存后更新后端与前端表格、统计卡片

### F7 进度状态与徽标

- F7.1：状态枚举：`简历已投递`、`评估中`、`Offer`、`已拒绝`
- F7.2：状态以胶囊徽标呈现（`rounded-full`、浅背景 + 深色文字 + 浅色边框）：
  - `评估中`：浅黄底金黄字（amber）
  - `简历已投递`：浅蓝底蓝字（sky）
  - `Offer`：浅绿底绿字（emerald）
  - `已拒绝`：浅红底红字（rose）

### F8 搜索

- F8.1：搜索输入框带搜索图标，占宽约 40%-50%，占位符「搜索公司、岗位或备注...」
- F8.2：关键词匹配公司、岗位、备注三个字段（大小写不敏感）
- F8.3：输入后表格实时过滤（防抖约 300ms）

### F9 进度筛选

- F9.1：下拉选择器「全部进度 ▾」，选项为「全部进度 + 四种状态」
- F9.2：选择后表格过滤至对应状态；「全部进度」时显示全部

### F10 时间排序

- F10.1：下拉选择器「时间：新到旧 ▾」，可切换「新到旧 / 旧到新」
- F10.2：按投递时间排序，同分时按记录 id 稳定排序

### F11 导出 CSV

- F11.1：「导出 CSV」按钮（浅蓝灰浅色背景）
- F11.2：导出当前检索结果（同时满足搜索词与进度筛选的行）为 CSV 文件下载
- F11.3：CSV 列：时间、公司、岗位、进度、下一步、备注；工作表编码为 UTF-8（带 BOM，便于 Excel 打开中文）

### F12 空状态

- F12.1：无数据时表格区域显示空状态提示（如「暂无投递记录，点击右上角新增」），不显示「虚构示例数据」文案

## 非功能需求

- N1：前端沿用现有技术栈（React 19 + Tailwind v4 + Vite），组件与现有模块风格一致
- N2：后端沿用 FastAPI + JSON 文件持久化模式，数据存 `data/投递进度/` 或 `data/jobs.json`（plan.md 定）
- N3：后端不做业务逻辑，仅负责增删改查与文件读写
- N4：前端字段定义与 API client 分离，类型集中在 `types.ts`
- N5：所有 UI 文案为中文
- N6：统计卡片数字实时来自后端数据

## 不做的事

- 删除记录（无删除按钮，入口）

## 验收标准

- AC1：点击侧边栏「投递进度」进入本页，不再是占位提示
- AC2：Header 小副标「秋招投递记录」、主标题「秋招投递进度」、描述与「+ 新增记录」按钮，样式符合设计稿
- AC3：5 张统计卡片显示各组定义的数字，空数据时全部为 0
- AC4：表格列头为「时间 | 公司 | 岗位 | 进度 | 下一步 | 操作」，公司名称加粗
- AC5：点「+ 新增记录」弹出表单，提交后表格与统计卡片更新，`data/` 下出现该记录
- AC6：点「编辑」弹出预填表单，保存后表格与统计卡片更新，后端文件同步
- AC7：4 种状态的徽标颜色与文案符合设计稿
- AC8：输入搜索词后，表格只显示公司/岗位/备注匹配的记录
- AC9：进度筛选下拉选择后，表格只显示对应状态
- AC10：切换排序方向，时间排列顺序正确翻转
- AC11：导出 CSV 文件包含当前筛选结果的行，中文可正常打开（带 BOM）
- AC12：无记录时显示空状态，「虚构示例数据」文案不出现
