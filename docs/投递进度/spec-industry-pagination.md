# 投递进度-新增行业字段与分页 Spec

## 背景

投递进度管理模块已上线，每条记录含 `投递时间 / 公司 / 岗位 / 进度 / 下一步 / 备注` 六列，一次性全量加载 `data/jobs.json` 并在前端完成搜索、筛选、排序。

本期做两个增量：
1. 新增一个**选填**字段「行业」，可展示在列表，并兼容已有记录（已有 12 条记录无此字段），让用户能编辑补填。
2. 投递记录列表**分页**展示，每页 15 条。

## 目标

- 记录新增「行业」字段：表单可填（自由文本、选填），列表可见，编辑可改，向后兼容已有记录。
- 投递记录列表分页展示，每页 15 条，带翻页交互。

## 功能需求

### F1 行业字段（数据层）

- F1.1：记录新增字段 `industry`（行业），为选填的字符串，缺省为空字符串。
- F1.2：已有记录（`data/jobs.json` 中无 `industry` 字段者）读取时视为空行业，不报错、不丢失原有数据。

### F2 行业字段（表单）

- F2.1：「新增记录」表单增加一个选填输入框「行业」（自由文本，可留空）。
- F2.2：「编辑记录」表单同样显示「行业」输入框。编辑已有旧记录时，若该记录无行业值，则输入框为空，用户补填后保存即可写入。

### F3 行业字段（列表展示）

- F3.1：投递记录表格增加「行业」一列，位于「岗位」与「进度」之间（列顺序：时间 | 公司 | 岗位 | 行业 | 进度 | 下一步 | 操作）。
- F3.2：行业为空的记录，该单元格显示占位符「—」（或留空但视觉对齐）。

### F4 分页

- F4.1：投递记录列表分页展示，**每页 15 条**。
- F4.2：当前页显示的数据 = 在「搜索 + 进度筛选 + 时间排序」结果之上做分页后的当前页记录。
- F4.3：表格底部提供分页控件，含「上一页 / 下一页」及当前页码 / 总页数信息；仅一页时控件可隐藏、禁用或显示"共 N 条"。
- F4.4：当搜索词、筛选、排序条件变化，或数据新增/编辑导致过滤结果变化时，若当前页码超出新结果的总页数，自动回退到有效页码（不出现空白页）。

### F5 统计与导出不受分页影响

- F5.1：页首「共 N 条」仍表示**过滤后全量**条数（非当前页条数）。
- F5.2：5 张统计卡片仍基于全量记录计算，不受分页影响。
- F5.3：导出 CSV 仍导出**过滤后全量**结果（当前筛选/排序满足的全部行），不受当前页限制。

### F6 导出 CSV 增加「行业」列

- F6.1：导出 CSV 的列结构调整为：时间、公司、岗位、**行业**、进度、下一步、备注。
- F6.2：行业为空的记录，导出时该单元格为空字符串（不写占位符）。
- F6.3：导出仍为过滤后全量结果，UTF-8 带 BOM。

## 非功能需求

- N1：沿用现有技术栈（React 19 + Tailwind v4 + Vite + FastAPI + JSON 持久化），风格与现有模块一致。
- N2：前后端类型定义同步，`industry` 在 `types.ts`、后端 Pydantic 模型与 `data/jobs.json` 中字段名一致。
- N3：所有 UI 文案为中文。
- N4：分页在客户端完成（沿用现有的全量加载 + 前端过滤架构），不引入服务端分页。

## 不做的事

- 不新增按「行业」筛选的下拉框（本期只做展示与录入）。
- 不做服务端分页 / 按行业聚合统计。
- 不修改其他模块。

## 验收标准

- AC1：新增记录表单出现「行业」输入框，选填；提交后新建的 JSON 记录含 `industry` 字段。
- AC2：投递记录表格新增「行业」列，位于岗位与进度之间；有值的显示该值，无值的显示占位符。
- AC3：编辑一条无行业值的旧记录，补填行业并保存，`data/jobs.json` 中该记录出现正确的 `industry` 值，列表同步显示。
- AC4：列表分页每页最多 15 条；总记录超过 15 条时出现分页控件，可翻页查看。
- AC5：分页结果在搜索/筛选/排序之上生效（例如搜索命中 30 条 → 分 2 页）。
- AC6：切换到不存在的页码时（如筛选后结果变少），当前页自动回退到有效页，不显示空白表格。
- AC7：页首「共 N 条」与统计卡片显示的是过滤后全量 / 全量数字，不因翻页而变化。
- AC8：导出 CSV 包含过滤后全部行（而非仅当前页）。
- AC9：导出的 CSV 存在「行业」列（位于岗位与进度之间）；行业为空的行该单元格为空字符串。
