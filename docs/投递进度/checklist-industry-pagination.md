# 投递进度-新增行业字段与分页 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性
- [ ] 后端 `JobRecordBody` 含可选 `industry` 字段；新增/更新记录落库含该字段（验证：POST 含 industry 的记录，查看返回 JSON）
- [ ] `job_storage.load()` 读取旧记录（无 industry）时补齐为空字符串（验证：用现有 `data/jobs.json` 调 load，断言每条的 industry 均为 `""` 且原始字段不变）
- [ ] 前端 `JobRecord` 类型含 `industry`（验证：`tsc` 编译通过）
- [ ] 新增表单含「行业」选填输入框（验证：打开新增弹窗可见「行业」输入框，可留空提交）
- [ ] 编辑表单预填「行业」；编辑无行业值的旧记录时输入框为空（验证：编辑旧记录，行业框为空，补填后保存）
- [ ] 表格新增「行业」列，位于岗位与进度之间；空值显示「—」（验证：查看表格列序与单元格显示）
- [ ] 分页控件存在且每页 15 条（验证：总记录 >15 时出现分页控件）

## 集成
- [ ] 搜索/筛选/排序变化时，「共 N 条」与统计卡片保持过滤后全量数字，不受翻页影响（验证：翻页后数字不变）
- [ ] 分页作用于过滤后结果：搜索/筛选命中超过 15 条时正确分页（验证：造出 >15 条过滤结果，观察分页页数）
- [ ] 页码越界自动回退（验证：切换筛选使结果变少，不出现空白页，自动落在有效页）
- [ ] CSV 导出含「行业」列，位于岗位与进度之间；空行业单元格为空字符串（验证：导出 CSV 查看列与空值单元格）

## 编译与测试
- [ ] 后端启动无错误（验证：`python -c "from src.api.job_routes import JobRecordBody"` 导入成功）
- [ ] 前端构建通过（验证：`npm run build` 或 `tsc` 无错误）
- [ ] 类型一致：`types.ts` 的 `JobRecord.industry` 与后端 `JobRecordBody.industry` 字段名一致（验证：对比两处字段名）

## 端到端场景
- [ ] 场景 1（新增+行业+分页）：新增若干含行业记录（累计 >15 条）→ 表格出现「行业」列并显示值 → 列表分 2 页以上 → 可翻页查看 → 页首「共 N 条」为全量数字
- [ ] 场景 2（编辑旧记录补行业）：编辑一条无行业值的旧记录 → 表单行业框为空 → 补填「互联网」保存 → 表格该行显示「互联网」，`data/jobs.json` 该记录含 `industry:"互联网"`
- [ ] 场景 3（导出）：导出 CSV → 文件含「行业」列，有值行显示、无值行为空，中文可正常打开（带 BOM）
- [ ] 场景 4（分页越界回退）：先翻到末页 → 输入搜索词使结果不足一页 → 表格自动显示全部结果（在有效页），无空白
