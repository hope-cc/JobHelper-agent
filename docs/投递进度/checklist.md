# 投递进度管理 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [ ] 后端 `GET /api/jobs` 返回全量记录（验证：启动后端，curl 返回 `{"jobs": [...]}`，空数据为 `[]`）
- [ ] 后端 `POST /api/jobs` 新增记录并持久化（验证：curl POST 后再次 GET，记录出现且含 id）
- [ ] 后端 `PUT /api/jobs/{id}` 更新记录（验证：curl PUT 修改 status 后 GET 确认变更；id 不存在返回 404）
- [ ] 后端校验：空公司/空岗位被拒绝、非法 status 被拒绝、非法日期格式被拒绝（验证：curl 各传一个非法值，期望 422）
- [ ] 前端 `MainArea` 的「投递进度」渲染真实页面而非占位页（验证：点侧边栏进入）

## 页面结构与视觉

- [ ] Header 展示小副标「秋招投递记录」、主标题「秋招投递进度」、描述文案、「+ 新增记录」按钮（验证：肉眼观察）
- [ ] 5 张统计卡片 `grid-cols-5` 排布，白底圆角浅灰边框（验证：肉眼观察）
- [ ] 表格列头：「时间 | 公司 | 岗位 | 进度 | 下一步 | 操作」，公司加粗，行 hover 高亮，分割线干净（验证：肉眼观察）
- [ ] 0 状态徽章颜色符合设计稿（实验观察）：
  - [ ] 评估中 → 浅黄底金黄字
  - [ ] 简历已投递 → 浅蓝底蓝字
  - [ ] Offer → 浅绿底绿字
  - [ ] 已拒绝 → 浅红底红字
- [ ] 空数据显示空状态提示，「虚构示例数据」文案不存在（验证：空库进入页面）

## 功能交互

- [ ] 「+ 新增记录」弹出表单，必填校验，提交后表格与统计卡片即时更新，`data/jobs.json` 出现该记录（端到端，见下场景 1）
- [ ] 「编辑」弹出预填表单，保存后表格与统计卡片更新（验证：改一字段保存，观察）
- [ ] 搜索「关键字」时只显示公司/岗位/备注匹配记录（验证：输入「字节」观察过滤）
- [ ] 进度筛选下拉只显示对应状态（验证：选「已拒绝」观察只剩红色徽章行）
- [ ] 排序下拉切换时间方向，排列顺序翻转（验证：两态互换观察首行变化）
- [ ] 统计数字实时派生：新增/编辑/筛选后「全部记录」等数字正确（验证：新增一条，全部=原+1；本月投递仅当月记录数）

## 编译与测试

- [ ] `cd frontend && npx tsc --noEmit` 无类型错误
- [ ] 后端 `python run.py` 无 import 错误，能正常启动
- [ ] `git status` 仅包含预期改动的文件

## 端到端场景

- [ ] 场景 1（新增+统计）：进入页面（空库）→ 全部卡片显示 0、表格空状态 → 点「+ 新增记录」填字节跳动/后端工程师/今天/简历已投递/等待一面 → 保存 → 表格出现一行蓝色徽章，全部=1，进行中=1，本月=1，`data/jobs.json` 有该记录
- [ ] 场景 2（筛选+搜索+导出）：已有若干条不同状态记录 → 搜索「后端」只剩相关行 → 再选「已拒绝」只剩拒绝行 → 点「导出 CSV」下载文件，用文本编辑器/Excel 打开，表头与行数与当前过滤结果一致，中文正常
- [ ] 场景 3（编辑+排序）：已有两条不同日期记录 → 「时间: 旧到新」行顺序与「新到旧」相反 → 编辑早的那条改晚日期 → 表顺序更新为最新在后
