# 个人信息管理-字段自定义 Spec

## 背景
当前「个人信息管理」页面的字段全部由代码预定义（`profileFieldConfigs.ts` 中写死的 `BASIC_INFO_FIELDS`、`INTERNSHIP_FIELDS`、`PROJECT_FIELDS` 等）。用户提出两点诉求：

1. 删除「实习经历」「项目经历」两个分区；
2. 基本信息区的字段不再由程序写死，改为用户在网页上自定义：可改标签、删除、调整顺序、新增自定义字段；每个字段保留「脱敏」勾选。

后端以 `data/personal/profile.json` 单文件存储整份档案；LLM 通过 `getPersonalInfo` 工具读取（敏感字段以 `***` 替换）、`browser_fill_form` 等工具按 `basic_info.xxx` 数据键取值。

## 目标
- 删除实习经历、项目经历分区及其前后端数据结构。
- 基本信息字段由用户维护并随档案持久化，摆脱代码写死。
- 保留并兼容现有脱敏机制（agent 读取时敏感字段值显示 `***`）。
- 保证 LLM 侧字段取值路径（键名映射）稳定、可解析、可识别。

## 功能需求
- **F1**：个人信息管理页面不再展示「实习经历」「项目经历」两个分区。
- **F2**：基本信息字段列表由用户维护并持久化。每条字段含稳定键（key）、展示标签（label）、输入类型、选项、顺序。键在字段创建时自动生成且永不改变；键用于存储、脱敏匹配与 LLM 取值，标签用于展示与语义识别。
- **F3**：用户可对任一基本信息字段（含预设的姓名/手机等 10 项）执行：修改标签、删除字段、调整顺序。
- **F4**：用户可新增自定义基本信息字段：填写标签，可选输入控件类型（单行文本 / 多行文本 / 下拉选择，下拉可填选项），默认单行文本。存储键由系统按标签自动生成：键名可直接使用中文标签（Python/JSON 均合法），仅需清洗点号、空白、换行等会破坏路径解析的字符（替换为下划线），标签重名时追加序号保证键唯一；键与标签分离，后续改名不影响键。
- **F5**：每个基本信息字段（预设或自定义）保留「脱敏」勾选；勾选后 agent 读取该字段值时显示 `***`，持久化文件中的原始值不变。
- **F6**：字段改名不改变其存储键，不影响已填写的值、不影响脱敏标记；删除字段同时清除其值及脱敏标记。
- **F7**：实习/项目数据不再被页面渲染、保存或 agent 读取，包括历史遗留数据。

## 非功能需求
- **N1**：仍以 `data/personal/profile.json` 单文件存储；数据结构向前兼容——新增字段元数据键、移除 `internship`/`project` 键。
- **N2**：现有 LLM 工具（`getPersonalInfo` / `browser_fill_form` / `browser_fill_dropdowns`）的取值与脱敏行为保持不变。
- **N3**：前端 `npm run build`（tsc+vite）与 `npm run lint` 通过；后端现有测试全部通过。
- **N4**：用户未做任何改动时，基本信息区默认展示现有的 10 个预设字段，与改动前一致。
- **N5**：LLM 取值兼容性——`getPersonalInfo` 返回内容同时包含 `basic_info`（键→值）与 `basic_fields_schema`（键→标签→类型→选项）；LLM 可通过标签反查键、以 `basic_info.<key>` 构造取值路径传给 `browser_fill_form`。字段改名不改键、删除即键整体消失（取值返回空并跳过填写），不破坏既有工具行为。

## 不做的事
- 不改动「教育经历」「奖项」「语言能力」分区的预设字段（仍由代码定义，沿用现有 EntrySection 机制）。
- 不改动「简历管理」模块及其「实习经历/项目经历」内容分类（独立模块）。
- 不改动自我评价区。
- 不新增字段类型（如日期、文件上传等），仅复用现有 text / textarea / select 三种。
- 不改动脱敏与取值逻辑本身，只让基本信息字段从「代码写死」变为「持久化可编辑」。

## 验收标准
- **AC1**：打开个人信息管理页面，看不到「实习经历」「项目经历」两个分区。
- **AC2**：基本信息区默认显示姓名/手机/邮箱等 10 个预设字段，每个字段带脱敏勾选与删除操作。
- **AC3**：新增一个自定义字段并保存后，刷新页面该字段仍在、内容保留。
- **AC4**：修改某字段标签并保存后，已填的值不丢失、脱敏勾选状态不变。
- **AC5**：调整字段顺序并保存后，刷新页面顺序保持。
- **AC6**：删除某字段并保存后，其值与脱敏标记一并清除，之后不再出现。
- **AC7**：对自定义字段勾选脱敏后，agent 通过 `getPersonalInfo` 读取时该字段值显示 `***`，且 profile.json 中原始值不变。
- **AC8**：保存后，`getPersonalInfo` 返回内容与 `profile.json` 中均不再包含 `internship`/`project` 键。
- **AC9**：后端现有测试全部通过；前端 `npm run build` 与 `npm run lint` 通过。
- **AC10**：改名某字段标签后，`getPersonalInfo` 返回中该字段的键名不变、schema 中标签已更新、值与脱敏保持；删除某字段后，其键从 schema 与值字典中消失，表单填写自动跳过对应项。
