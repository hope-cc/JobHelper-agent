# 投递表单填写工具 Spec

## 背景

JobHelper 目前已有：
- **个人信息管理**：用户在页面填写七类信息，持久化到 `data/personal/profile.json`，键名稳定语义清晰，供 agent 按键取值
- **工具系统**：`@tool` 装饰器 + ReAct 循环，已有 `openBrowser` / `click` / `getText` / `getPersonalInfo` / `dispatchTasks` 工具
- **局限性**：现有浏览器工具均为**无头、每次调用打开即关闭的无状态工具**，无法承载「打开 → 登录 → 填表 → 提交 → 确认」这种需要浏览器长期打开、且中间穿插多次人工介入的流程

本需求让 agent 能够**帮用户填写招聘平台的简历投递表单**。该流程天然需要人工参与（手机扫码登录、检查表单、点击确认提交），因此浏览器必须以**有头方式保持打开**，跨多次工具调用和多个用户轮次存活。

## 目标

- 提供一个投递表单填写工具，以有头方式打开投递页面
- 支持跨轮次的有状态流程：打开 → 用户登录 → 自动填表 → 用户检查提交 → 确认投递成功
- 表单自动填写基于已保存的个人信息，匹配不到的字段交由用户在浏览器中补填
- 保持个人信息脱敏设计：agent 在对话中只看到脱敏后的字段，真实值仅由工具内部读取用于填写
- 投递成功后返回「投递成功」，并预留结果记录接口（本期不落库，接口留桩）
- 投递完成后自动回收浏览器会话，防止资源泄漏

## 功能需求

### F1：打开投递页面

- 工具首次调用时接收目标投递页 URL，以有头方式打开浏览器并导航到该 URL
- 浏览器会话按 `conversation_id` 隔离：不同会话互不影响
- 打开成功后返回登录指引（提示用户用手机扫码/短信登录，完成后回复「继续」）
- 页面打开失败（URL 非法、超时、网络错误）时返回明确错误信息

### F2：有状态流程推进

- 工具为单个有状态工具，内部按会话维护阶段状态机：**等待登录 → 表单填写 → 等待提交 → 投递完成**
- 每次调用时，根据当前阶段与页面真实状态决定下一步，而不是仅凭用户措辞推进
- 阶段状态与浏览器会话绑定，跨多次工具调用、多个用户轮次保持

### F3：登录等待

- 工具不自动化登录，任何登录方式（扫码/短信）均可
- 处于「等待登录」阶段时，用户回复「继续」后工具先检测页面：表单已出现 → 进入填表；表单未出现 → 返回提示（请确认已登录并刷新页面）
- 用户通过聊天回复来推进流程（如「已登录」「继续」）

### F4：表单自动填写

- 检测到表单出现后，读取已保存的个人信息（`profile.json`），按表单字段与个人信息字段的匹配关系自动填写
- 能匹配到的字段自动填入真实值；匹配不到的字段（如期望薪资、到岗时间）在返回结果中列出，由用户在浏览器中补填
- 返回填写报告，包含：已填字段清单、未匹配字段清单、下一步指引（检查无误后点击提交，回复「已提交」）
- 个人信息不存在时返回提示，引导用户先去「个人信息管理」页填写保存

### F5：投递成功检测

- 处于「等待提交」阶段时，用户回复后工具检测页面是否出现投递成功标识（启发式：页面文本中「投递成功 / 已投递 / 提交成功」等字样或页面跳转）
- 检测到成功 → 返回「投递成功」
- 未检测到 → 返回未确认提示，请用户确认是否已点击提交

### F6：投递结果记录接口（预留）

- 投递成功时调用一个记录接口，本期为空实现（不落库、不报错）
- 接口签名与数据结构预留好，供后续「投递进度」模块接入

### F7：会话生命周期管理

- 投递完成（成功或失败终止）后，关闭浏览器并清理会话
- 会话空闲超过设定时限（默认约 10 分钟）自动关闭浏览器、清理会话，防止资源泄漏
- 提供取消手段：用户表达取消意图时，可结束当前投递会话并关闭浏览器

### F8：用户推进指引

- 流程每个阶段结束时，返回的文本都明确告诉用户当前状态和下一步该做什么
- 用户误推进（如表单还没出现就回复「继续」）时，返回纠错提示而非报错

## 非功能需求

- **N1：事件循环安全** — 浏览器对象由后台专属事件循环持有，不绑定请求的事件循环，跨轮次调用不会因事件循环切换而失效
- **N2：会话隔离** — 不同 `conversation_id` 的投递会话互不影响，各自拥有独立的浏览器实例与阶段状态
- **N3：个人信息脱敏** — 工具返回给对话（agent 可见）的字段内容保持脱敏（敏感字段显示 `***`），真实值仅由工具内部读取、写入表单，不出现在对话任何输出中
- **N4：可扩展性** — 新增招聘平台无需修改工具框架代码；表单字段匹配规则集中定义、易于扩展
- **N5：错误隔离** — 单个工具执行失败不中断整个对话，错误以信息形式返回给 LLM 解释给用户
- **N6：运行环境约束** — 有头浏览器窗口出现在后端运行所在机器上（当前为本地开发环境）；该功能面向本地使用场景
- **N7：状态可观测** — 流程每个阶段的推进都有明确文本反馈，用户始终知道当前状态与下一步

## 不做的事

- **不自动化登录** — 扫码 / 短信等登录动作完全由用户完成，工具不尝试自动登录或记住登录态
- **不落库投递结果** — 本期投递成功后仅返回「投递成功」并调用空实现的记录接口，不写入任何存储
- **不做平台专用适配** — 不为特定招聘平台编写专用选择器或专属逻辑，统一走通用字段匹配
- **不做完整投递进度模块** — 「投递进度」是独立的后续模块，本工具只在其接口上预留挂接点
- **不做多标签页 / 多浏览器复用** — 每个会话一个浏览器实例，不管理多个标签页或复用已有实例
- **不自动点击提交** — 提交动作由用户人工检查和点击，工具不代替用户确认投递
- **不改动现有工具系统架构** — 工具注册、ReAct 循环、SSE 事件流均保持不变，仅新增机制

## 验收标准

- **AC1：** 首次调用带 URL，弹出有头浏览器窗口并导航到该 URL
- **AC2：** 会话跨多次工具调用和多个用户轮次保持打开，浏览器窗口不关闭
- **AC3：** 表单出现后，工具自动填写匹配字段，返回报告列出「已填字段」和「未匹配字段」
- **AC4：** 填写报告及对话输出中敏感字段以 `***` 显示，真实值不出现在任何工具输出中
- **AC5：** 用户点击提交并回复后，工具检测到成功标识并返回「投递成功」
- **AC6：** 投递成功后浏览器自动关闭、会话清理
- **AC7：** 会话空闲超时后浏览器自动关闭
- **AC8：** 用户取消投递时浏览器关闭、会话清理
- **AC9：** 每个阶段返回的文本都包含当前状态与下一步指引
- **AC10：** 表单未出现时用户回复「继续」，返回纠错提示而非报错
- **AC11：** URL 非法或页面加载失败时返回明确错误信息，对话不中断
- **AC12：** 个人信息未保存时返回引导提示
- **AC13：** 投递成功时调用预留的记录接口且不报错、不影响流程
