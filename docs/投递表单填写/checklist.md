# 投递表单填写工具 Checklist

> 每项通过运行代码或观察行为验证，聚焦系统行为。

## 实现完整性

- [ ] `submitApplication` 工具已注册（验证：`ToolRegistry.discover()` 后 `list_definitions()` 含 `submitApplication`）
- [ ] 有状态流程可跨多次工具调用推进（验证：同一会话连续调用工具，阶段从 WAITING_LOGIN 推进到 WAITING_SUBMIT 再到 SUBMITTED）
- [ ] 表单自动填写返回报告，含「已填字段」和「未匹配字段」清单（验证：对含表单的页面调用，观察返回文本）
- [ ] 报告与对话输出中敏感字段显示 `***`，真实值不出现（验证：观察返回文本中的手机/证件等字段值）
- [ ] 投递成功检测有效（验证：对含「投递成功」文本的页面返回 True，对普通页面返回 False）
- [ ] 记录接口预留调用不报错（验证：投递成功路径执行后无异常、流程正常结束）

## 集成

- [ ] 工具壳正确获取会话ID并调用 BrowserManager（验证：无会话且 URL 为空 → 返回「首次调用需要URL」类错误文本，不崩溃）
- [ ] BrowserManager 正确编排 fill / detect / recorder（验证：真实流程中填写、成功检测、清理依次生效）
- [ ] `routes.py` 注入 ContextVar，图执行链路正常（验证：发任意消息 SSE 流正常返回，无未初始化/空会话错误）
- [ ] 现有纯文本对话功能不受影响（验证：发一条不触发工具的普通消息，行为与改动前一致）

## 编译与测试

- [ ] 后端可正常启动、无导入错误（验证：启动 uvicorn，观察日志无 ImportError）
- [ ] 全部 `src/browser/*` 模块可独立导入（验证：`PY -c "import src.browser.manager, src.browser.fill, src.browser.detect, src.browser.recorder, src.browser.session, src.browser.context"`）
- [ ] 字段匹配纯函数单测通过（验证：`match_field` 对已知标签返回正确键值）

## 端到端场景

- [ ] **场景 1（完整投递）**：用户「帮我投递 <表单页URL>」→ 弹出有头浏览器窗口并导航 → 用户手动登录 → 回复「已登录」→ 工具检测表单并自动填写 → 返回报告（已填/未匹配/下一步指引）→ 用户在浏览器中点击提交 → 回复「已提交」→ 工具检测成功 → 返回「投递成功」→ 浏览器窗口自动关闭（验证：用真实浏览器逐步骤走完，观察每步返回文本与窗口状态）
- [ ] **场景 2（表单未出现就推进）**：登录未完成时用户回复「继续」→ 返回纠错提示（如「未检测到表单，请确认已登录并刷新」），不报错（验证：步骤观察）
- [ ] **场景 3（取消投递）**：流程任意阶段用户表达取消 → 返回「已取消」，浏览器窗口关闭、会话清理（验证：观察窗口关闭，再次调用工具按首次处理）
- [ ] **场景 4（空闲超时）**：打开浏览器后 10 分钟无操作 → 浏览器窗口自动关闭（验证：等待观察）
- [ ] **场景 5（个人信息未保存）**：删除/清空 profile.json 后走到填表阶段 → 返回引导「请先在个人信息管理页填写保存」而非报错（验证：构造状态观察）
- [ ] **场景 6（URL 非法）**：首次调用传非法 URL（无协议头/乱码）→ 返回明确错误文本，浏览器不打开（验证：步骤观察）
