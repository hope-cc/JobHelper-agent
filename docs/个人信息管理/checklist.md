# 个人信息管理 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性

- [ ] `ProfilePage` 已实现且被 `MainArea` 的 `profile` 分支引用（验证：构建通过，点导航进入页面）
- [ ] 七个分区渲染：基本信息、教育经历、实习经历、项目经历、奖项、语言能力、自我评价（验证：进入页面观察）
- [ ] 枚举字段为下拉、自由文本为输入框（验证：观察性别 / 学历 / 证件类型 / 精通程度等）

## 分区交互

- [ ] 教育 / 实习 / 项目 / 奖项 / 语言各分区可「添加」空表单（验证：点击添加按钮，出现空条目）
- [ ] 已添加条目可编辑，修改后显示更新（验证：改某字段值，观察变化）
- [ ] 已添加条目可删除（验证：点击删除，条目消失）
- [ ] 自我评价为多行文本框，可输入多行（验证：输入换行内容）

## 保存与加载

- [ ] 点「保存」后 `data/personal/profile.json` 生成，为含所有分区键的字典（验证：查看文件内容）
- [ ] 保存成功 / 失败有明确提示（验证：观察页面提示）
- [ ] 重新进入页面自动回填已保存内容（验证：填写→保存→刷新→值仍在）
- [ ] 删除条目后保存，JSON 数组中移除该条（验证：查看文件）
- [ ] 保存的 JSON 中条目不含前端 `id` 字段（验证：查看文件）

## 集成

- [ ] 后端 `GET/PUT /api/personal` 可用（验证：curl 请求返回 200 与字典）
- [ ] 前端类型检查通过（验证：`npx tsc --noEmit`）
- [ ] 前端生产构建通过（验证：`npx vite build`）
- [ ] 其余功能不受影响（验证：新聊天、简历管理页面仍正常）

## 端到端场景

- [ ] 场景 1（首次填写保存）：进入页面 → 填写基本信息 + 添加一条教育经历 → 点保存 → `data/personal/profile.json` 生成且结构正确 → 刷新页面内容回填
- [ ] 场景 2（增删与顺序）：进入页面 → 添加三条项目经历 → 删除中间一条 → 保存 → JSON 中数组剩两条且顺序正确
