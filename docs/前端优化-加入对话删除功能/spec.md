# 个人信息管理导航项 + 批量删除会话 Spec

## 背景
JobHelper 前端目前有三个主导航项（新聊天、简历管理、投递进度），其中简历管理和投递进度仅显示空白占位页。左侧聊天记录区域展示历史会话列表，但不支持删除操作——后端 `storage.py` 和 `routes.py` 均无删除相关的函数和接口。

## 目标
1. **新增"个人信息管理"导航项**：在左侧导航区新增第四项，指向空白占位页，与现有的"简历管理""投递进度"行为一致
2. **支持批量删除会话记录**：在聊天记录区域增加批量删除模式，用户可以勾选多个会话并一键删除

## 功能需求
- **F1**：在左侧上方导航区新增第四项"个人信息管理"，点击后右侧主区域显示空白占位页
- **F2**：在聊天记录标题旁新增"批量删除"开关（Toggle），默认关闭。开启时出现删除按钮和各会话的勾选框；关闭时隐藏并清空勾选
- **F3**：用户可左键点击勾选框来勾选/取消勾选单个会话。勾选与点击会话标题互不干扰
- **F4**：点击"删除"按钮后，向后端发送删除请求，删除所有被勾选的会话。删除完成后刷新列表、清空勾选、若当前会话被删则回退到"新聊天"视图，批量删除模式保持开启
- **F5**：后端 `storage.py` 增加 `delete_conversation()` 函数，`routes.py` 新增 `DELETE /api/conversations/{conversation_id}` 路由
- **F6**：前端 `client.ts` 新增 `deleteConversation(id)` 函数

## 非功能需求
- **N1**：新增导航项在视觉和交互上与现有三项完全一致，复用 NAV_ITEMS 模式
- **N2**：勾选框和删除按钮不与现有聊天记录项冲突，勾选框与标题有清晰分隔
- **N3**：删除接口遵循现有路由和存储层的代码风格
- **N4**：删除操作直接删除 JSON 文件，不可恢复；删除不存在的会话 ID 时幂等成功
- **N5**：当前查看的会话被删除后，前端自动回退到"新聊天"视图

## 不做的事
- 不提供单个会话的独立删除（右键菜单、滑动删除等）
- 不提供"全选 / 取消全选"按钮
- 不提供删除确认弹窗
- 不提供删除撤销或回收站功能
- "个人信息管理"页面仅显示空白占位
- 不提供拖拽多选、Shift 范围选择等高级交互

## 验收标准
- **AC1**：左侧导航区出现第四项"个人信息管理"，点击后右侧显示占位页
- **AC2**：聊天记录标题旁存在"批量删除"开关，默认关闭，此时无勾选框和删除按钮
- **AC3**：打开开关后，每个会话项左侧出现可点击的勾选框，开关下方出现"删除"按钮
- **AC4**：未勾选任何会话时点击"删除"，按钮无响应或提示无选中
- **AC5**：勾选会话后点击"删除"，对应会话从列表消失，后端 JSON 文件被删除
- **AC6**：被删除的会话是当前打开的会话时，右侧视图自动回到"新聊天"页面
- **AC7**：删除完成后勾选状态清空，批量删除模式保持开启
- **AC8**：关闭批量删除开关后，勾选框和删除按钮全部隐藏，界面恢复常规状态
