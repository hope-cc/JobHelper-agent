# 下拉框探测与填写优化 Spec

## 背景

投递表单填写工作流（`src/prompt/prompt.py` SubmitFlow）中：

- 步骤 7（`browser_probe_dropdowns`）：目前只从当前页面快照识别非标准下拉框候选，**不展开、不取选项**，返回的是 `ref/标签/当前值` 清单。
- 步骤 8（`browser_fill_dropdowns`）：目前依赖「展开后从**下拉框自身 ref 子树**裁剪快照并提取选项」，但真实站点（如 zhiye.com）的非标准下拉框展开后，选项弹层渲染在 **body 底部的全局 Portal** 中（快照里表现为根节点下第二个最高层级 generic，与页面主体平级），**不在下拉框触发元素的子树内**，导致现有代码识别不到选项、填不进去。

用户已确认的改造目标：
1. 步骤 7 改为**逐个展开未填写的下拉框 → 全局快照（`browser_snapshot` target=body）→ 按缩进规则从弹层提取选项纯文本**，把 `ref + label + 选项清单` 一起返回给 LLM。
2. 步骤 8 改为**自适应多种下拉填法规则**（输入+回车；输入→过滤→点圆圈→点确定；以及常见变体），提高鲁棒性。

## 目标

- 让 `browser_probe_dropdowns` 能为每个未填写的下拉框提供**候选选项清单**，供 LLM 依据个人信息匹配目标值。
- 让 `browser_fill_dropdowns` 能覆盖真实站点多种交互形态（而非固定某一条规则），并保持「动作成功即算成功」的判定（用户已确认）。
- 全程保持浏览器只保留一个页面、弹层逐个开/收，不做多余点击，不污染已填写的字段。

## 功能需求

### F1：只对未填写的下拉框展开取选项
- 从当前页面快照用既有结构规则识别下拉框候选（combobox/listbox，或 generic[cursor=pointer] 且浅层含选项容器）。
- 只对 **is_empty 为真的下拉框**逐个执行展开抽取；已填写的下拉框保留其当前显示值但**不展开、不点击、不取选项**。
- 「逐个」语义：展开一个 → 取特征 → 收起它 → 再展开下一个。

### F2：展开后从全局快照定位弹层
- 点击下拉框触发展开后，调用 `browser_snapshot` 取全局快照（不按 ref 裁剪子树）。
- 从全局快照中按**缩进层级规则**定位弹层：过滤首个最外层（页面主体及其子树），保留**第二个最高层级的 generic 子树**作为弹层内容区（真实站点形态：`e1 → 页主体 e3 / 弹层 e1739`）。
- 若全局快照中未出现第二个最高层级 generic（弹层未弹出或结构不同），记录失败原因，不中断其余下拉框。

### F3：从弹层提取选项纯文本
- 从弹层子树内提取选项：优先收集 `generic ... [cursor=pointer]: 文本` 行的文本（该特征在真实站点上天然排除「全国/全部省市/已选…/清空已选/取消/确定」等弹层 UI 噪声）。
- 对其他弹层形态提供兜底（复用既有 `listitem` / `option ` 解析逻辑；均无法解析则返回空）。
- 输出选项时**剥离全部无关内容**：去掉 ref、DOM 树结构、层级前缀、属性标注，每个选项只剩纯文本字符串。
- 提取后过滤空值、去重。

### F4：探测结果返回 ref、label、选项
- 每个未填写下拉框返回：`ref`、`label`（字段标签）、`options`（纯文本文档列表）、`display`（当前显示值，未填写时为空/占位）。
- 抽取失败带失败原因（不抛异常、不中断），转向下一个下拉框。

### F5：解析多种自适应交互规则
- 输入为 LLM 生成的 `items: [{ref, data_key 或 value}]`（data_key 后台取真实值，否则字面 value）。
- 展开下拉框后按顺序尝试下列形态直到选中目标值：

| 优先级 | 调用形态 | 动作序列 |
|--------|---------|---------|
| P1 | 直接从弹层点选 | 弹层选项命中目标值 → 点击选项文本（或选项行/圆圈 ref）→ 若存在「确定/确认」按钮则点击 |
| P2 | 输入后点击过滤结果 | 弹层有搜索/过滤输入框 → 输入目标值 → 等待渲染 → 重新快照 → 命中选项 → 点击（文本/圆圈）→ 若有加/确定按钮则点击 |
| P3 | 输入后直接回车 | 弹层有搜索输入框 → 输入目标值 → 直接发送回车（选择高亮项）→ 若有确定按钮则点击 |
| P4 | 文本定位兜底 | 目标文本在页面某处可点击 → `browser_find` / JS 点击兜底 |

- 判定方式：**动作成功（点击/回车的无工具层错误）即算填写成功**（用户已确认），计入已填，不回读显示值核验。
- 每条 items 独立尝试；对无效 ref（非下拉框、不在候选识别外）跳过并在报告中标注（沿用既有行为）。

### F6：填写失败后报告
- 每条处理结果分：已填（filled）/ 未匹配（unmatched）/ 失败（failed）/ 跳过（skipped），附 ref、目标值（敏感时脱敏）、原因。
- 目标值来自 data_key 且为敏感字段时，后台真实值替换填写、报告中显示 `***`（沿用现有脱敏逻辑）。
- 返回文本结构保持「填写结果 + 已填 / 未匹配 / 失败 / 跳过」分组摘要。

### F7：流程提示文本同步更新
- 更新 `src/prompt/prompt.py` 中 SubmitFlow 步骤 7/8 文字及 `_SUBMIT_FLOW_NEXT` 的下一步提示：
  - 步骤 7：browser_probe_dropdowns 返回未填写下拉框的 ref、label **以及可用选项清单**。
  - 步骤 8：由 LLM 依据步骤 7 的 label+选项+个人信息决定目标值，传给 browser_fill_dropdowns。
- 逻辑不改、文案与新增语义一致。

## 非功能需求

- N1 弹层逐个拉起/收起：展开一个 → 全局快照 → 收起 → 下一个；不得同时存在多个弹层叠加，避免遮挡影响选中。
- N2 宽容度：单个下拉框或提取失败不影响其余下拉框处理。
- N3 脱敏链：敏感值仅后台取用/写入表单，真实值不进入对话文本或工具报告。
- N4 兼容与既有行为一致：无效 ref 跳过、识别到的已填下拉框不被误展开/误导点。
- N5 浏览器仍只保持一个页面；本功能依赖既有 MCP 会话，不改 client 与浏览器生命周期。
- N6 性能：每下拉框展开后快照各一次往返，不无限重试（每种形态最多尝试一次）。

## 不做的事

- 不实现日期选择器/级联联动控件（如换算→课程）的填写。
- 不做弹层显示值核验（用户已确认「动作成功即算」）。
- 不做通用昵称映射表（label 与个人信息数据键的匹配由 LLM 上下文决定，沿用现状）。
- 不做「先展开全部候选再统一全局快照」的批量形态（用户已确认逐个展开）。

## 验收标准

- AC1：对真实站点（zhiye.com 意向工作地点），browser_probe_dropdowns 能定位到弹层，并返回各下拉框的 ref/label/选项。
- AC2：options 全部为纯文本（无 ref、无缩进、无 DOM 树），不含「全国/全部省市/已选地区/清空已选/取消/确定」等。
- AC3：probe 仅对未填写的下拉框执行一次展开；已填下拉框不展开点击。
- AC4：probe 对象下拉框无弹层时返回失败原因而非中断整体。
- AC5：browser_fill_dropdowns 中 P1/P2/P3 任一命中对应路径即可填写，且返回 filled。
- AC6：无效 ref 项计入跳过，不误点击其他元素。
- AC7：单个填写失败不影响其余 item 继续处理。
- AC8：敏感字段显示仍为 `***`，对话与报告无真实值。
- AC9：浏览器全程只保留一个页面。
